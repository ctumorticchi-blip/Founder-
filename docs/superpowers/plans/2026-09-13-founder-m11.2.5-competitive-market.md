## Tâche 1 — Types + fonctions pures `identifiedCompetitors.ts`

**Types** (`src/types/competition.ts`) :
- `Competitor` gagne `readonly qualityLevel: number` (0-1, additif).

**Fichier neuf** `src/engine/competition/identifiedCompetitors.ts` :

```ts
export const IDENTIFIED_COMPETITORS_PER_MARKET = 4;

export function createIdentifiedCompetitors(
  marketId: string,
  aggregate: AggregateCompetition,
  rng: Rng,
): readonly Competitor[]

export function advanceIdentifiedCompetitors(
  competitors: readonly Competitor[],
  aggregate: AggregateCompetition,
  rng: Rng,
): readonly Competitor[]

export function computeCompetitorMarketShare(
  competitor: Competitor,
  marketCompetitors: readonly Competitor[],
  aggregate: AggregateCompetition,
): number
```

Noms d'entreprises : nouveau petit catalogue dans le même fichier (préfixe/
racine/suffixe, patron `strategicAccountIdentity.ts` mais SANS contact —
un concurrent identifié n'a pas d'interlocuteur nommé). `strength` initial
tiré `rng.nextFloat(0.2, 1)` par concurrent (variété), `qualityLevel`
initial `rng.nextGaussian(aggregate.averageQuality, 0.15)` clampé [0,1].
`advanceIdentifiedCompetitors` : drift gaussien faible sur `strength`
(`rng.nextGaussian(0, 0.03)`, clamp [0.05, 1] — jamais 0 pour éviter une
part de marché qui s'effondre à rien puis remonte bizarrement) et
`qualityLevel` (mean-reverting vers `aggregate.averageQuality`, même
esprit que le drift de l'agrégat).

**Tests** (`test/engine/competition/identifiedCompetitors.test.ts`) :
- `createIdentifiedCompetitors` : déterministe (même seed → même résultat,
  `toEqual`), produit `IDENTIFIED_COMPETITORS_PER_MARKET` concurrents,
  `strength`/`qualityLevel` dans [0,1], noms non-vides et distincts entre
  eux (au moins la plupart — pas un test flaky sur l'improbable collision).
- `computeCompetitorMarketShare` : somme des parts de tous les concurrents
  d'un marché == `aggregate.totalCapturedRevenueShare` (`toBeCloseTo`,
  identité mathématique du §1 de la spec) ; un concurrent à `strength`
  double d'un autre a une part double (toutes choses égales) ; part
  toujours >= 0.
- `advanceIdentifiedCompetitors` : déterministe, reste dans les bornes sur
  200 mois simulés (comme le test existant d'`advanceAggregateCompetition`),
  `qualityLevel` dérive statistiquement vers `aggregate.averageQuality` sur
  de nombreux essais partant d'un point éloigné.

## Tâche 2 — Intégration `game.ts` / `simulateMonth.ts`

`src/engine/simulation/types.ts` : `GameState` gagne
`readonly competitors: Readonly<Record<string, readonly Competitor[]>>`.

`src/engine/simulation/game.ts` (`createInitialGameState`) : même boucle
que `competitionsById` (ligne ~34), ajoute
`competitorsById[market.id] = createIdentifiedCompetitors(market.id, competitionsById[market.id], rng.fork(\`competitors:init:${market.id}\`))`.

`src/engine/simulation/simulateMonth.ts` (boucle existante ligne ~130-132,
juste après `advanceAggregateCompetition`) :
```ts
const existing = state.competitors[marketId] ?? [];
competitors[marketId] = existing.length > 0
  ? advanceIdentifiedCompetitors(existing, competitions[marketId]!, rng.fork(`competitors:${marketId}`))
  : createIdentifiedCompetitors(marketId, competitions[marketId]!, rng.fork(`competitors:backfill:${marketId}`));
```
(backfill des sauvegardes existantes, §4 de la spec — pas de fabrication
d'historique, première apparition réelle dans cette partie).

**Tests** (`test/engine/simulation/game.test.ts`,
`test/engine/simulation/simulateMonth.test.ts` — étendre les fichiers
existants, pas de nouveau fichier) :
- `createInitialGameState` peuple `competitors` pour chaque marché fourni.
- `simulateMonth` fait évoluer les concurrents existants (résultat
  différent de l'état précédent sur un horizon assez long pour un drift
  visible, ou au moins structurellement valide à chaque mois).
- Backfill : un `GameState` construit à la main avec `competitors: {}`
  (simulant une sauvegarde migrée) produit, après un `simulateMonth`, des
  concurrents non-vides pour chaque marché — sans avoir jamais appelé
  `createInitialGameState`.
- **Non-régression explicite** : diff dédié confirmant qu'aucune ligne de
  `computeOfferDemand`/`resolveOfferOutcome`/`demandShare` n'a changé sur
  ce milestone (même discipline que M11.2.4.3, vérifié en Tâche 6 par
  `git diff` sur ces fichiers précis, pas un test automatisé).

## Tâche 4 — Projection bruitée (`intelligence.ts`)

```ts
export type CompetitivePositionLevel = "economy" | "standard" | "premium";
export type MarketShareLevel = "low" | "moderate" | "high";

export interface CompetitorView {
  readonly id: string;
  readonly name: string;
  readonly positionLevel: CompetitivePositionLevel;
  readonly shareLevel: MarketShareLevel;
}

export function projectCompetitorView(
  competitor: Competitor,
  marketShare: number,
  skillAverage0To100: number,
  rng: Rng,
): CompetitorView
```

Bucket `qualityLevel` bruité en 3 paliers (`< 0.4` economy, `< 0.7`
standard, sinon premium — même style que `POSITIONING_INDEX`/paliers
existants). Bucket `marketShare` bruité en 3 paliers calibrés sur l'ordre
de grandeur réel (`totalCapturedRevenueShare` typiquement 0.3-0.95, donc
la part d'UN concurrent parmi N est généralement petite — paliers `<0.1`
low, `<0.25` moderate, sinon high — à ajuster si les tests d'observation
d'une baseline réelle montrent une distribution différente).

**Tests** (`test/engine/intelligence/intelligence.test.ts`, étendre) :
- `projectCompetitorView` déterministe pour un rng donné.
- Le nom n'est jamais altéré par le bruit (identique à `competitor.name`).
- Bruit plus grand à compétence 0 qu'à compétence 100 (observable sur de
  nombreux essais — écart-type empirique, même patron que les tests
  existants d'`estimate`).
- Chaque palier est atteignable avec une valeur d'entrée calibrée pour y
  tomber.
