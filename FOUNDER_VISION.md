# FOUNDER_VISION.md — Constitution produit durable

Ce document encode la vision produit approuvée de FOUNDER. Il change
rarement et ne doit être modifié que par une décision produit explicite
(voir `CLAUDE.md` §PRODUCT DECISION REQUIRED), jamais par déduction
technique.

## Ce qu'est FOUNDER

FOUNDER est une simulation progressive d'entrepreneuriat et de
construction d'empire économique.

Le joueur commence : **18 ans, sans études, sans argent.**

Progression :

```
individu (survie/emploi) → premier business → fondateur → employeur
→ manager/CEO → propriétaire de plusieurs entreprises
→ allocateur de capital → potentiellement empire mondial
```

FOUNDER doit permettre de créer de nombreux types d'entreprises grâce à
un **constructeur économique universel**, pas un simple catalogue rigide
de business figés.

## Complexité progressive

**Niveau individu**
- argent ; emploi ; temps ; compétences ; opportunités.

**Fondateur**
- offre ; clients ; prix ; ventes ; équipement ; cash.

**Petite équipe**
- recrutement ; capacité ; locaux ; productivité ; management.

**PME**
- managers ; départements ; BFR ; dette ; budgets ; stratégie.

**Grande entreprise / groupe**
- CEO ; filiales ; acquisitions ; gouvernance ; international.

**Propriétaire / allocateur de capital**
- dividendes ; participations ; portefeuille d'entreprises ; allocation
  de capital ; investisseurs ; plus tard marchés publics/gouvernance/
  pouvoir.

## Principes directeurs (non négociables sans PRODUCT DECISION REQUIRED)

- Moteur économique déterministe : toute conséquence économique vient du
  moteur, jamais d'un jet non seedé ni d'un texte généré.
- Causalité visible : le joueur doit pouvoir comprendre pourquoi un
  résultat s'est produit à partir de son propre état (temps investi,
  capacité, satisfaction, réputation...).
- L'IA narrative explique et raconte ; elle n'est jamais la source de
  vérité économique.
- La complexité se débloque progressivement — jamais tout exposé dès le
  début.
- La croissance impose de vraies contraintes : temps, capacité, cash,
  management, locaux, dette, BFR, concentration doivent réellement
  compter et pouvoir faire mal.
- Pas de plafond artificiel permanent (ex. 25 salariés) — les vraies
  limites sont organisationnelles (management, capacité, structure),
  pas un nombre arbitraire codé en dur.
- Les managers obtiennent une autonomie partielle ; les CEO pourront
  plus tard diriger à l'intérieur d'objectifs/budgets/niveaux de risque
  imposés par le propriétaire (le joueur).
- Les mauvaises décisions de managers/CEO doivent être causées par leur
  compétence, l'information dont ils disposent, les instructions reçues,
  et le contexte — jamais par une RNG arbitraire destinée à punir le
  joueur gratuitement.
- Les dividendes relient l'économie de l'entreprise au patrimoine
  personnel du joueur.
- Posséder plusieurs entreprises doit progressivement transformer le
  joueur en allocateur de capital, pas seulement en gestionnaire
  d'une entreprise à la fois.
- Mobile-first : toute UI doit fonctionner et rester lisible dès ~390px
  de large.
- Langage UI compréhensible, toujours métier — jamais technique (aucun
  id, aucun nom de champ interne, aucun jargon de moteur affiché au
  joueur).

## Ce que la vision n'impose pas encore

La vision décrit une direction, pas un plan détaillé de chaque
mécanique. Le détail (formules, constantes, découpage exact en slices,
noms de types) est une décision technique/produit locale, autorisée sans
validation (`CLAUDE.md`), tant qu'elle sert honnêtement ces principes.
